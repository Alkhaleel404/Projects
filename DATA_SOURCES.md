## Coordinate systems, caching, and missing data

- FEMA query geometry is submitted with `inSR=4326` and requested with `outSR=4326`; response coordinates and polygon structure are checked before display. Invalid geometries are dropped; if a non-empty response has no usable features, the app reports an error.
- FloodNet sensor longitude/latitude fields are checked for plausible NYC bounds and paired only when `sensor_id` matches a Queens sensor metadata row. Missing or malformed coordinates are not plotted. Sensors are not associated with route segments.
- NWS responses are normalized into a bounded number of periods/alerts; malformed responses produce visible source-specific errors.
- FEMA and FloodNet cache for one hour, NWS forecast one hour, and NWS active alerts five minutes using Streamlit's in-process cache. No persistent cloud cache is configured.
- Missing source results, unavailable sources, stale/fresh claims, and demo records are kept distinct. A source outage does not turn a simulated record into a live observation.

## Cloud and privacy

No cloud host, database, geospatial routing service, secret, or paid product is used/configured. Optional Streamlit Community Cloud deployment is documented in the README but has not been executed. App-server requests use fixed reference areas and do not transmit a user address or geolocation. FloodLens loads USGS The National Map tiles in the browser; tile requests can reveal a visitor's IP address and viewed tile coordinates to the tile service. The service is subject to USGS policies and availability.
